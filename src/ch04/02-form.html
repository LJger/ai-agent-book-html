除非存在明确的安全、权限或性能理由；即使要做专用工具，粒度也偏向整合

第四章 ·「能力的表达形式：专用工具、通用执行器与 Skill」

通用性有边界：这四种情况退回专用工具

默认往通用的一端靠；只在安全权限、平台差异、使用频率极高、参数复杂这四种情况下退回专用工具

第四章 ·「能力的表达形式：专用工具、通用执行器与 Skill」

参数复杂时，JSON 比命令行可靠

同一组嵌套参数示意
{ "name": "create_alert", "arguments": { "name": "CPU 告警", "conditions": [{ "metric": "cpu", "op": ">", "value": 0.9 }], "notify": { "channels": ["email", "im"], "message": "主机 \"web-1\" CPU 超过 90%" } } }
schema 规定了类型与结构；一些推理引擎还会限制采样，强制生成合法格式
单引号、双引号、反斜杠……转义规则比 JSON 复杂，Linux、Mac、Windows 还各不相同
折中：在 Skill 里要求先把结构化参数写进 alert.json，再 alertctl create --from-file alert.json
反过来：对人类编写者
工具 schema（代码）
{ "name": "create_alert", "parameters": { "type": "object", "properties": { ... }▯ 少了一个 }
解析失败：模型报错，整个 Agent 无法运行
Skill（自然语言）
1. 先确认分支已经合并 2. 再执形部署，部署后检查健康状态
局部小错：Agent 照常运行
无论是否会编程都能写、能改可以在 AI 生成的 Skill 上修改
