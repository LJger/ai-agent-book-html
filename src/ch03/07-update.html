不是扁平的向量碎片，也不是图谱节点：记忆、资源、技能都映射为目录和文件，每个条目拥有唯一 URI

viking:// 是虚拟 URI形式像 http:// 或 file://，却不指向具体的物理位置：框架在背后决定从内存、磁盘还是远程加载；L0/L1/L2 也由框架按访问频率和检索深度自动分配
每个目录下自动生成 .abstract（L0）和 .overview（L1），形成从根到叶的层次化摘要

供 Agent 规划决策

增量更新：把每次知识变更当成一个 PR

把知识库当成代码库Markdown 知识库、用户记忆文件、规则文档都进入 Git：差异审查 · 版本历史 · 责任追溯 · 一键回滚生产环境不应让任何一个模型绕过审核，直接改主分支或线上向量库
1
Proposer Agent 提交 PR

先检索相关的已有知识，提出尽可能小而完整的 diff；同步维护链接、索引、时间元数据和证据引用

2
Reviewer Agent 独立审核

拿变更前的知识、diff 和原始证据逐条核对；退回时给出指向具体证据和行号的可执行意见

3
双方迭代至收敛

只有 Reviewer 明确批准才可合入；设最大迭代次数或成本预算，超限转人工，不能默认放行

4
合入后再发布

CI 检查格式、链接、元数据、权限标签（代码形式还要类型检查和测试），再增量重建受影响的分块、摘要和向量

定期整理：回到原始数据的全量整理

多次局部正确的修改，会累积出全局问题同一事实散落在多个文件新旧说法同时存在摘要逐渐偏离原始证据目录结构不再适合当前规模≈ 第九章“睡眠学习”在知识管理中的实现
1去重、去旧与合并示意

删除、归并或重写重复与过时条目，重建链接、入口页和索引页；删的是可服务的知识表达，不是原始证据

2回到原始数据核查示意

不在摘要之间相互改写，逐段对照原始对话、轨迹与文档；分批扫描也要保留覆盖清单，而不是随机抽样

3冲突解决与场景限定示意

不“保留最新一条”、不让模型猜：追溯来源，两者都成立就写明适用场景，证据不足就保留待确认

仍走 PRProposer 提交重组 diff，异源 Reviewer 结合原始证据审核大 diff 拆分按目录或主题拆成多个 PR，共享同一份整理计划和覆盖清单回放验收重建全量索引后回放典型检索与问答用例触发条件每周 / 每月，或新增条目数、冲突数、检索质量下降超过阈值
