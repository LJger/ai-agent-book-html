跳过原理也要记住的三条核心结论

技术门槛提示：后面的原理是全书技术密度最高的部分之一，可以先只记结论

1系统提示词和工具定义
一旦确定就不要改点击翻面
哪怕多一个空格

任何改动都可能改变 token 序列，使首个不同 token 及其后的缓存无法复用

改动越靠前，延迟和成本影响通常越大（具体幅度视模型与配置而定）

You are a helpful␣assistant…
2动态信息
永远追加到末尾点击翻面
时间戳、用户状态……

变化的内容作为新消息追加到对话末尾，而不是修改已有的系统提示词

systemtools…历史…+ 新消息：当前时间 10:31
3使用标准 API 格式
不要自行拼接消息点击翻面
根本问题：偏离训练格式

结构化消息由 Chat Template 翻译成训练时见过的固定 token 序列；拼成 USER: … ASSISTANT: … 会削弱多步思考能力

缓存只认字节：拼接稳定照样命中，不稳定（向前缀注入动态内容）才失效

背后的直觉：模型会把已经处理过的内容缓存起来，下次只需要处理新增的部分

实验 2-2 ★：注意力，就是一次“找重点”

读到“怎么样”时，前面哪些词对理解它最重要？

向量含义在这个例子中
Query（查询）当前词发出的“搜索请求”“怎么样”问：哪个词和我最相关？
Key（键）每个词的“标签”，用于被搜索匹配“北京”的标签偏向“地名”，“天气”的标签偏向“气象”
Value（值）每个词的“内容”，匹配成功后被提取匹配到“天气”后，提取它的语义信息

对 Value 加权求和 → 这个位置的输出

为什么 Key 和 Value 需要缓存？

每生成一个新词，它的 Query 都要与前面所有词的 Key 匹配、再对所有 Value 加权求和。每次从头算所有 K 和 V，计算量随上下文不断增长——把它们缓存起来，新词直接复用。
