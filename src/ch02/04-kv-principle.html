第二章 ·「KV Cache 的原理与约束」

无缓存是 N²，有缓存每组 K/V 只算一次

设想第 6 轮对话、上下文已累积 2000 token：无缓存时，每生成一个新 token 都要重算这 2000 个 token 的 K、V——前 5 轮没变，也要从头再来
123456
不使用 KV Cache · 累计算了0组 K/V（∝ N²）
使用 KV Cache · 累计算了0组 K/V（每个 token 一次）

但每个新 token 的注意力仍要遍历全部缓存：每步线性增长——长上下文解码越来越慢，KV Cache 的显存与带宽成为瓶颈

第二章 ·「KV Cache 的原理与约束」

改动第 k 个 token，为什么之后全部失效？

层是串联的流水线：每一层处理每个词时，都综合了它前面所有词的信息

变动点
需要重新计算和计费的 token0
可以复用的缓存0

变动点越靠前，要重算和计费的 token 越多，延迟影响通常也越大——本章实验中实测可达数倍。所以：系统提示词一旦定下来就不要改。
