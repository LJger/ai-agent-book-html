进程式隔离：好处、代价与两个平面

好处
  • 每个 Agent 可以独立开发和测试
  • 新增能力不需要改动现有代码
  • 出了故障也不会把错误状态传染给其他 Agent
  • 真正并发执行：上下文完全独立，不存在资源竞争
代价
  • 信息同步：各 Agent 如何对任务状态保持一致的理解？
  • 信息在传递中会不会丢失或重复？
  • 调试更难：要翻多个 Agent 的日志才能拼出全过程

→ 接口规范、数据格式和通信协议的设计变得至关重要

控制平面之三：执行终止沿创建关系级联

新的生命周期树 · context.Background()
首选
  1. 主 Agent 发出 terminate
  2. 子 Agent 在当前步骤的安全点响应（Go：轮询 ctx.Done()）
  3. 清理资源：关闭浏览器会话、写入未完成文件、释放锁
  4. 返回确认（ack）后退出
兜底

直接终止进程，仅在子 Agent 对优雅信号无响应时使用

代价：可能遗留悬挂资源与未完成写入

取消一个 Agent，它派生的所有子 Agent 随之取消，从根上杜绝无人认领的孤儿 Agent；后台 Agent（类似 nohup）显式声明不随父级终止
