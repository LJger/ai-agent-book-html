失败模式三：同质趋同

示意
18/ 30 个同时上线的 Agent 创建了同名 Git 分支；写作实验中还会不约而同地用相同标题
共因失效

由共同模型和脚手架引发：同一模型、相似上下文生成的多个审核意见，不能自动视为相互独立的证据

对策

引入模型、上下文和数据来源的差异；用命名空间、资源配额和速率限制，防止相同决策同时冲击共享资源

失败模式六：理解债与认知投降——不是 Agent 的失败，而是人的失败

Agent 交付的系统实现工程师的理解示意
理解债

Agent 循环交付代码的速度越快，工程师对系统实际实现的理解就落后得越远

认知投降

习惯了用 Agent 代劳，逐渐放弃独立思考与审查，软件质量失控

“你可以外包你的思考，但不能外包你的理解。”—— Andrej Karpathy

管理 Agent 就像管理技术员工：既不能越俎代庖，也不能放手不管。合格的技术管理者要理解并指导系统架构，而不是仅仅用 PUA 的方式指挥 Agent——技术基本功很重要
