从 Manager 的视角看，调用一个 Agent 和调用一个普通工具没有本质区别。

Manager：调用一个 Agent，就像调用一个工具

理解整体任务→拆解为子任务→选择合适的 Agent 执行→跟踪进度 · 处理异常→整合为最终结果

顺序协调形态：一个接一个，Manager 决定下一步

Manager Agent任务理解 → 分解 → 调度 → 综合工具集: [call_agent_A, call_agent_B, call_agent_C, search, write_file]
Step 1Sub-Agent A角色：数据收集
  • 搜索技术文档
  • 提取关键信息
Step 2Sub-Agent B角色：分析处理
  • 对比分析数据
  • 生成统计报告
Step 3Sub-Agent C角色：报告生成
  • 撰写最终报告
  • 格式化输出
顺序执行流
  1. Manager 调用 A
  2. A 返回数据
  3. Manager 传给 B
  4. B 返回分析
  5. Manager 传给 C
  6. C 返回报告

Manager 视角：调用 Agent = 调用工具
发请求 → 获响应

控制流是线性的，简单明了，适合子任务之间有清晰先后依赖的场景
