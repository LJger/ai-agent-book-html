工作流：确定性的编排

预设的异常分支 / 交还人类
✗ 被拦下：节点之间的流转由代码写死
严格的流程控制

“付款前不能预订”这类业务规则由代码强制执行，不依赖 LLM 的判断

安全性

提示注入或模型犯错，最多只能影响当前节点内部；攻击面被限制在单个节点内

缺乏变通性

改签、航班取消需要替代方案时，只能走预设的异常分支或交还人类

主流 Agent 框架简要对比

框架 / 平台核心定位编排模式开发方式适用场景
Codex Harness：驱动 Codex App / CLI / IDE 扩展的运行时；三条集成路径：codex exec（脚本与 CI 的一次性任务）、Codex SDK（第三方应用启动、恢复、流式处理任务）、app-server（JSON-RPC 持久会话、事件流与审批回调）
