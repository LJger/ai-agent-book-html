构建有效 Agent 的三个原则

保持简单

从最简单的方案开始，只在确实必要时才增加复杂度；直接的 API 调用优于复杂的框架

每多一层抽象，都是以后调试时新的盲区
保持透明

明确显示规划步骤、执行日志和决策轨迹——也是让用户建立信任的前提

黑箱里的错误，外部既无法定位也无法纠正
设计好工具接口（ACI）

Agent-Computer Interface：从 Agent 的视角设计接口，命名和参数要直观

容易误用的地方，从设计上让错误无法发生

如何选择模型：在自己的任务上评估

闭源模型

OpenAI（GPT / o 系列）、Anthropic（Claude 系列）：能力通常领先，但成本较高、受限于厂商的 API 策略

不要只看排行榜，要在你自己的任务上做评估（第七章）
开源模型

与闭源的差距在 6 个月以内，成本显著更低；可私有化部署、支持微调；DeepSeek、Kimi、GLM 是国内 Agent 能力较强的模型

工具调用能力差异很大，选型前务必实测
策略边界

有能力 ≠ 产品允许你调用：网络安全、模型蒸馏、模型提取、隐私数据、高风险操作，各家边界不同

测试是否愿意执行、接口是否暴露、条款是否允许；备好人工接管或替代模型
支持思考（Reasoning）

绝大多数 Agent 需要支持思考的模型：多步思考、工具选择都依赖它

例外：单步简单任务；固定位置点击的简单 GUI 操作
多模态能力

需要理解图片、音频或视频时，多模态就是硬性要求，不同模型差异很大

选型时把它当作门槛条件，而不是加分项
