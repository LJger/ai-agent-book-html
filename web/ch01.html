    第一章 ·「工具：Agent 的手脚」

    工具调用（Tool Calling）的四步

    1. 1
      声明工具

      在上下文里告诉模型有哪些工具：名称、用途和参数

    2. 2
      模型决定调用

      要不要调用、调哪个、传什么参数，由模型自主判断

    3. 3
      结果追加到上下文

      工具执行完毕，结果作为新消息追加

    4. 4
      模型基于结果回复

      据此决定下一步：继续调用，或给出回答

    上下文（每次调用模型时发送的全部内容）
    systemYou are a helpful assistant.示意
    tools[{ name: "get_weather", parameters: { city: "string" } }]
    user北京今天天气怎么样？示意
    assistanttool_calls: [{ function: "get_weather", arguments: { city: "北京" } }]
    Agent 框架执行 get_weather
    tool{ tool_call_id: "call_1", content: '{"temp":28,"sky":"晴"}' }
    assistant北京今天 28°C，晴。
    模型自主决定：要不要调用、调哪个、传什么参数

    开发者只需要定义工具和执行工具调用；这个“请求 → 调用 → 执行 → 追加 → 再请求”的循环，就是 ReAct 的基础

      如何选择模型：在自己的任务上评估

      闭源模型

      OpenAI（GPT / o 系列）、Anthropic（Claude 系列）：能力通常领先，但成本较高、受限于厂商的 API 策略

      不要只看排行榜，要在你自己的任务上做评估（第七章）
      开源模型

      与闭源的差距在 6 个月以内，成本显著更低；可私有化部署、支持微调；DeepSeek、Kimi、GLM 是国内 Agent 能力较强的模型

      工具调用能力差异很大，选型前务必实测
      策略边界

      有能力 ≠ 产品允许你调用：网络安全、模型蒸馏、模型提取、隐私数据、高风险操作，各家边界不同

      测试是否愿意执行、接口是否暴露、条款是否允许；备好人工接管或替代模型
      支持思考（Reasoning）

      绝大多数 Agent 需要支持思考的模型：多步思考、工具选择都依赖它

      例外：单步简单任务；固定位置点击的简单 GUI 操作
      多模态能力

      需要理解图片、音频或视频时，多模态就是硬性要求，不同模型差异很大

      选型时把它当作门槛条件，而不是加分项
