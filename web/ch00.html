    引言 · 第 5–6 段（Pine 的工程实践）

    条件一：选择对能力上限要求足够高的真实业务

    第一，选择对 Agent 能力上限提出足够高要求的真实业务，并持续获取真实反馈。
    以 Pine 为例
    • 一项任务可能持续数小时乃至数周
    • 与多个利益相关方反复沟通
    • 长时间通话 · 复杂表单操作 · 多轮邮件往来
    • 关键数字准确 · 操作可控 · 始终维护用户利益
    示意

    足够复杂的场景会持续暴露模型能力与业务要求之间的差距 → 促使团队构建 harness，沉淀出稳定的系统设计原则业务需求很容易被下一次模型升级覆盖 → 差距很快消失，团队较难积累稳定的系统设计原则

    PART 03

    核心公式

    不管模型如何升级、产品形态如何创新，
    成功的 Agent 系统几乎都遵循同一种架构模式
    好的设计原则本就应该穿越模型的迭代周期——它们描述的不是某个模型的用法，而是智能系统与世界交互的基本模式。

    从尘埃到智能体

    图灵奖得主、强化学习之父 Richard Sutton：宇宙演化经历了 4 个阶段

    Agent
    生成代码
    新的 Agent
    生成代码
    下一个 Agent
    理解自身的运作机制 · 根据目标创造全新的智能体，甚至改进自己

    本书的使命：帮助你理解和掌握这种创造的原则

    PART 04

    全书结构

    十章，围绕两个相互衔接的问题：
    如何构建 Agent，如何提升 Agent 能力
    先用评估建立可度量的反馈，再通过模型后训练、持续进化和多 Agent 协作，分别从模型参数、单体系统和群体系统三个层面扩展能力。

    两个相互衔接的问题：构建，然后提升

    第一部分　如何构建 Agent 第二部分　如何提升 Agent 能力

    评估提供反馈，后训练、持续进化与协作据此扩展能力

    第一部分“如何构建 Agent”第一至六章

    从基本概念出发，依次讨论上下文、记忆与知识、工具、Coding Agent，以及观察与动作空间的扩展

    第二部分“如何提升 Agent 能力”第七至十章

    先用评估建立可度量的反馈，再通过模型后训练、基于运行经验的持续进化和多 Agent 协作扩展能力
